This is a Terraform provider built on **terraform-plugin-framework** (not SDKv2). It manages Entra-authenticated database users and role memberships on Azure SQL and Azure PostgreSQL Flexible Server. `CLAUDE.md` at the repo root is the working contract — read it when a check below points at it.

The checks below are the failure classes this repo actually ships. Apply them in addition to the standard methodology; they do not replace any of it.

## Unknown vs. null in `ValidateConfig` and validators

**Highest-value check in this repo.** `ValidateResourceConfig` runs on the *validate* walk, before any provider is configured and before any data source is read, so every value sourced from another object (`object_id = data.azuread_group.x.object_id`) is **unknown** at that point, not null. Code that treats unknown as absent rejects valid configs at plan time.

- Any new or edited branch in `internal/resources/*/resource.go` `ValidateConfig`, or any `ValidateString`/`ValidateX` in `internal/validators/`, must skip on `IsUnknown()` before it can reach a "required" or "invalid value" diagnostic. `IsNull() || IsUnknown()` guarding an *error* path is the bug shape; `IsNull() || IsUnknown()` guarding an *early return* is correct.
- `correctness`, at least `warning`. Trace: PR #14 — `internal/resources/user/resource.go` rejected `type = "group"` whenever `object_id` came from an `azuread` data source.
- Cross-attribute rules belong in `ValidateConfig`; per-attribute rules in `internal/validators/`. A per-attribute validator that reaches for a sibling attribute is misplaced.

## Engine layering

`internal/resources/**` may import `internal/database` (the `DatabaseConnector` interface) but **must never** import `internal/database/mssql` or `internal/database/postgres`. `internal/provider/provider.go` is the only place that names an engine package. An import that breaks this is `api-contract`, `warning` — it is the invariant that keeps "add an engine" a one-`case` change.

Any change to the `DatabaseConnector` interface in `internal/database/connector.go` must land in **both** engine implementations in the same PR. A one-sided change is `correctness`.

## Import ID ↔ `Create()` ID symmetry

Each resource's `ImportState` parses an ID that `Create()` assembles. If a PR changes either side, verify the other matches, and that the format comment on the import handler still describes it. Formats are documented in `CLAUDE.md` → "Key conventions". Drift here is `correctness`, `warning`, and only reproduces on `terraform import`, so it will not show up in a plan.

## SQL identifiers and retry

- Identifiers cannot be parameter-bound. User, role, and schema names go through the engine's quoting helper — `[name]` for MSSQL, `"name"` for PostgreSQL. Raw concatenation into DDL is `security`, `critical` even when the input looks constrained. (Values are a different matter and bind normally: `@p1` / `$1`.)
- Retry is for transient faults only — MSSQL error `1205`, PostgreSQL SQLSTATE `40P01`. Widening `internal/database/retry.go` to retry auth, syntax, or missing-object errors is `correctness`, `warning`.

## No real identifiers, anywhere

`tfplugindocs` mirrors `MarkdownDescription` strings and `examples/**` verbatim into public registry pages. A real UPN, employee name, Entra group or app display name, object/tenant/subscription UUID, server hostname, or database name in **any** file — `.go` (including comments), `.tf`, `.sh`, README, CHANGELOG, tests, fixtures — is `security`, `critical`. The approved placeholder table is in `CLAUDE.md` → "No personal or company-specific identifiers anywhere". Anything outside that table that looks real, is.

## Schema descriptions

Every new or changed schema attribute needs `MarkdownDescription` (not `Description`) — a missing one renders as a blank column on the public registry page, and `Description` renders as unformatted text. `api-contract`, `warning`.

`docs/` is generated by `tfplugindocs`; a hand-edit there is `warning`. (Missing regenerated docs is not — CI's `generate` job already hard-fails on it.)

## Go module coupling

If a PR raises the `go` directive in `tools/go.mod` past the root `go.mod`, CI fails with an opaque toolchain error inside `tools/`. Both move together. Worth one line in the body when you see a one-sided bump — the failure is cryptic enough to be worth naming.

## Tests

Do not apply a blanket "every change needs tests" rule — it is wrong for docs, examples, workflow, and dependency PRs, and this repo's acceptance suite hits real Azure and is `workflow_dispatch`-only, so it cannot gate a PR. Apply this instead:

- **Unit test expected** when the PR adds or changes branching logic in `internal/resources/**`, `internal/validators/**`, or `internal/database/{credential,retry}.go`. Anchor the finding to the specific function, `correctness`, `warning`. Unit tests here use `tfsdk.Config` + `tftypes` values directly (see `internal/resources/user/resource_test.go`) and community mocks for SQL — never a live database.
- **A validation or plan-time fix needs a test that fails without it.** For the unknown-vs-null class specifically, a test using a *known* value does not exercise the fix; the value must be `tftypes.UnknownValue`. A PR that fixes plan-time behaviour and only adds known-value cases is `warning` — the regression is uncovered.
- **Table-driven coverage must span every arm the change touches.** If one `switch` arm handles several values (`case "group", "service_principal":`), a test for one of them leaves the others unguarded. `warning`.
- **Acceptance test expected** only when the PR changes SQL emitted against a live engine (`internal/database/{mssql,postgres}/**`) or adds a resource/attribute with observable engine behaviour. Tests live in `internal/provider/*_acceptance_test.go`, are `TestAcc`-prefixed, and require the env vars listed in `tests/acceptance/README.md`. If a new acceptance test needs a prerequisite that is not in that README's table, the PR must add it — otherwise the test fails for everyone else. `warning`.
- Note in the body when a PR touches engine SQL and no acceptance run is linked. It is an ask, not a blocker.

## Release-path files

`.goreleaser.yml`, `terraform-registry-manifest.json`, and the GPG signing steps in `.github/workflows/release.yml` are copied from HashiCorp's scaffolding because the Terraform Registry consumes them and rejects unsigned or malformed releases. An edit to any of them with no stated reason is `warning` — the failure surfaces only after a tag is published, which cannot be retracted (registry indexers cache by commit SHA).

## Out of scope here

Skip these — they are covered elsewhere and flagging them is noise: gofmt/golangci-lint output (CI runs it), missing copyright headers (`goheader` lints them), and `CHANGELOG.md` entries (release-please generates them from Conventional Commits).
